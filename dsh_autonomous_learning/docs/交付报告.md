## 五、真实测试结果

命令：

```powershell
cd <repo>
$env:PYTHONPATH = "<repo>"
python -m pytest dsh_autonomous_learning\tests
```

结果：`96 passed in 3.01s`（完整输出见 `docs/pytest-output.txt`）。

覆盖要点：
- 无证据不得升级为 verified；单来源不足以核验 fact；观点/假设永久不可验证；
- 公式重算通过/失败、容差、无期望值判 inconclusive；
- 冲突：数值（1.80 vs 0.90）、极性、否定；矛盾项不会被当成重复合并；
- 备份/恢复后数据与索引一致；缺失向量会被判为完整性问题；
- 权限：assisted 删除需确认令牌、代码执行被拒；lab 模式可信代码可执行；
- 密钥（`sk-…`/Bearer/私钥）禁止入库，审计日志脱敏；
- 预算：单轮任务上限、每日预算、按轮无进展停止；
- 断点续跑：running 任务恢复为 retrying；失败任务重置；
- 调度：到期一次性任务执行后自动关闭；
- 工具契约：55 个规范要求工具全部存在；参数校验与未知工具返回结构化错误；
- CLI 冒烟：`tools list` 返回真实工具清单。

## 七之一、DSH 插件化（本轮新增）

引擎以 **两个 Cordis 插件包**安装进 profile，而不是只靠手工 MCP 连接：

| 包 | 类型 | 作用 | 状态 |
| --- | --- | --- | --- |
| `@local/dsh-autolearn` | 配置型 bundle | 插入 `@deepseek-ai/dsh-mcp-client` 行（`serverName: autolearn`、stdio、env、cwd） | `application: applied`，`include:autolearn-mcp` active |
| `@local/dsh-autolearn-approval` | Host 插件 | `tools/pre-execute` 对高风险调用返回 `ask` | `application: applied`，active |

### 设置卡（v1.1.0）

- Client：`client.js` 注册 `plugins.bundle.config`（key `@local/dsh-autolearn`），
  渲染「运行模式 / 数据目录 / 每日预算」三项 + 保存/恢复默认；
- Host：`index.js` 注册 `/dsh-autolearn/api/settings`（GET/POST，64KB 上限，
  枚举/范围/绝对路径校验），原子写 `data/settings.json`；
- 引擎：`config.load_config` 合并 settings.json，`runtime.apply_settings()`
  在每轮 `run_round` 前刷新模式与预算；数据目录变更仅在建连时生效（返回
  `data_dir_pending` 提示）。
- 验证：Node 侧 `settings_test.mjs` 覆盖默认值、读写回环、非法模式/预算/相对路径；
  Python 侧 `tests/test_settings.py` 8 个用例覆盖覆盖顺序、非法值忽略、运行中热更新、
  数据目录 pending；全量 `96 passed`。
- 状态：包版本 1.1.0 已安装，安装器返回 `restart-required`（Client/Host 新模块需重启加载）。

## 七之二、assisted 审批接入 DSH 审批 UI

### 做了什么

1. **宿主闸门插件**：`<repo>/plugins/approval`（Host-only Cordis bundle）
   - 监听 `tools/pre-execute`，对 `mcp__autolearn__*` 中 `execute` / `destructive`
     以及显式列出的工具返回 `{ kind: 'ask', reason }`；
   - DSH 用**自己的审批弹窗**询问用户；用户拒绝 → 工具不执行；
   - 判定数据来自引擎导出的 `tool_risks.json`，不重复维护风险表。
2. **引擎委派**：`DSH_AL_HOST_APPROVAL=1`（已写入 MCP 连接环境）时，
   `PermissionManager` 不再要求 `confirm_token`，把最终把关交给宿主。
3. **审批 user-only**：MCP 工具移除 `request_confirmation` / `approve_confirmation`，
   智能体没有任何"自我授权"通道；备用入口是用户亲手执行的
   `main confirmations approve <token>`，待确认项持久化在 SQLite。
4. **fail-closed 三重检查**（引擎侧，缺一即退回本地令牌流程）：
   - profile 的 `dsh.profile.bundles` 是否包含闸门；
   - `cordis.patch.yml` 是否 `disabled: true`；
   - 闸门代际 ≥2 时，心跳必须新鲜（旧代无心跳则按代际标记放行）。

### 真实验证

| 验证项 | 结果 |
| --- | --- |
| 插件安装 | `install_bundle` → `application: applied`，profile package.json 与 bundles 已含 `@local/dsh-autolearn-approval` |
| 插件激活 | Host 日志：`[autolearn-approval] active: prefix=mcp__autolearn__ tools=63 askRisks=execute/destructive` |
| 判定函数（Node，真实清单 8 条） | 全部 PASS：`run_code_test` / `invalidate_knowledge` / `update_knowledge` → ask；`save_knowledge` / `search_knowledge` / `get_runtime_info` / 其它前缀 → 放行；`allowTools` 覆盖生效 |
| 引擎委派（真实 MCP 客户端） | `get_runtime_info` → `delegate_approval_to_host=true`、`host_gate_installed=true`；`invalidate_knowledge` 无需 token 成功（status=stale） |
| 本地令牌流程 | 96 项 pytest 覆盖：待确认项跨进程持久化、`approve`/`reject`/`consume`、宿主不可用时 fail-closed |
| 审批弹窗渲染 | **未做浏览器点击验证**（本轮没有可用的 `mcp__autolearn__*` 工具调用触发弹窗） |

### 限制与后续

- 闸门新增心跳/代际标记属于**新模块代际**：安装器返回 `restart-required`，
  重启 DSH 后生效；当前进程里运行的是上一代（同样会 `ask`，只是不写心跳）。
- 弹窗的实际视觉与拒绝路径需要在一次真实工具调用中人工点一次确认；
  在此之前只能声明"判定与注册已验证"，不能声明"UI 交互已验证"。

## 九、已知问题（如实）

1. 真实模型调用未验证：环境没有向子进程暴露 `COMMANDCODE_API_KEY`，默认走 mock；
   配置 `model.provider=openai` 且设置环境变量后才走真实接口。
2. 语义向量用的是特征哈希（非神经模型）；同义改写召回有限，已用 BM25 混合缓解。
   接入嵌入服务后需 `rebuild_vector_index`。
3. 代码执行只是进程级隔离，不是沙箱；默认禁止不可信代码。
4. 中文关键词用二元组切分，未接分词器。
5. 冲突检测是规则式（数值/极性/否定），复杂语义矛盾需人工/模型介入，且系统保证保留双方证据。
6. 定时任务需外部触发（DSH/计划任务调用 `run_scheduler_tick`），不做常驻后台循环。
7. 不做 OCR、不做真实回测/交易、不实现图数据库与 UI 面板。
8. 审批闸门的**弹窗交互**尚未人工点击验证；心跳代际需重启 DSH 后生效
   （旧代闸门仍会正常 `ask`，只是不写心跳）。
